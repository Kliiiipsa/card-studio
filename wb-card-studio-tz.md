# ТЗ на доработку WB Card Studio

**Проект:** https://wb-card-studio.vercel.app/
**Стек (по факту сборки):** Next.js (App Router), Tailwind + shadcn/ui, генерация изображений через fal.ai
**Дата аудита:** 31.07.2026
**Вне скоупа:** регистрация/авторизация и раздел с ценами — дорабатываются отдельно.

## Как пользоваться этим документом в Claude Code

Каждая задача самодостаточна: в ней есть проблема, шаги воспроизведения, что сделать и критерий приёмки.
Не отдавайте весь файл одним промптом — берите по одной задаче за раз:

```
Прочитай wb-card-studio-tz.md, выполни задачу P0-2 целиком.
Перед изменениями покажи, какие файлы будешь править.
После — проверь критерии приёмки из задачи и отчитайся по каждому пункту.
```

Задачи внутри одного приоритета независимы, порядок P0 → P1 → P2.

# P0 — блокирует использование продукта

## P0-1. Результаты генерации нигде не сохраняются

**Проблема.** Сгенерированная карточка живёт только в React-стейте. `localStorage` и `sessionStorage` пусты, картинка отдаётся по прямой ссылке с внешнего CDN (`https://v3b.fal.media/files/...`). Обновление страницы = потеря работы. Раздел «Мои проекты» после генерации остаётся пустым.

**Воспроизведение.**
1. Открыть `/generator`, заполнить «Название товара» и «Преимущества».
2. «Написать промпт» → «Сгенерировать карточку», дождаться результата.
3. Нажать F5 — результат исчез.
4. Перейти в `/dashboard` — «Пока нет проектов».

**Что сделать.**
1. Завести хранилище файлов (Vercel Blob / Cloudflare R2 / Supabase Storage — на ваш выбор, Vercel Blob проще всего при деплое на Vercel).
2. После успешного ответа fal.ai — скачать изображение на сервере и переложить в своё хранилище. Наружу отдавать **только свой** URL, ссылку на `fal.media` в клиент не пробрасывать.
3. Завести БД (Postgres/Supabase) с минимальной схемой:
   - `projects`: `id`, `owner_id` (nullable до появления авторизации), `title`, `product_name`, `category`, `audience`, `benefits[]`, `pains[]`, `created_at`, `updated_at`
   - `generations`: `id`, `project_id`, `type` (`cover` / `benefits` / `infographic` / …), `style`, `prompt`, `image_url`, `width`, `height`, `status`, `created_at`
4. Каждая генерация из `/generator`, `/infographics` и `/analysis` создаёт запись в `generations`. Если пользователь пришёл без проекта — создавать черновой проект автоматически (`Черновик от 31.07`).
5. `/dashboard` показывает реальный список проектов с превью последней генерации, датой и количеством карточек.
6. До появления авторизации привязывать проекты к анонимному `visitor_id` в httpOnly-куке, чтобы данные не терялись между визитами. При подключении регистрации этот `visitor_id` перепривязывается к пользователю.

**Критерий приёмки.**
- После генерации и F5 карточка на месте.
- Карточка видна в `/dashboard` и открывается из проекта.
- В DevTools → Network адрес картинки на своём домене, `fal.media` в клиенте не встречается.
- История генераций внутри проекта показывает все варианты, а не только последний.

## P0-2. Мобильная версия неработоспособна

**Проблема.** Три отдельных дефекта.

1. Сайдбар приложения объявлен как `hidden w-64 shrink-0 flex-col border-r bg-card/50 md:flex` — на ширине < 768px он полностью скрыт, а альтернативной навигации (бургер, нижний таб-бар) нет. Разделы «Инфографика» и «Анализ и улучшение» на телефоне недостижимы вообще.
2. Шапка приложения (заголовок + бейдж «AI подключён» + переключатель темы + «Новая карточка») не помещается в 390px: появляется горизонтальный скролл, кнопка обрезается.
3. На лендинге логотип «WB Card Studio» в шапке ломается в три строки и налезает на соседние элементы.

**Воспроизведение.** DevTools → device toolbar → iPhone 12 (390×844), пройти `/`, `/dashboard`, `/generator`.

**Что сделать.**
1. Добавить мобильную навигацию: кнопка-бургер в шапке (< `md`) → выезжающая панель (`Sheet` из shadcn/ui) с теми же пунктами, что в сайдбаре. Активный пункт подсвечен, переход по клику закрывает панель.
2. Шапку сделать адаптивной: на `< sm` скрывать текстовую подпись бейджа (оставить точку-индикатор), у кнопки «Новая карточка» на `< sm` оставить только иконку `+`. Заголовок страницы — `truncate`.
3. Логотип: `whitespace-nowrap` + уменьшенный кегль на `< sm`, подпись «AI для карточек» скрыть на мобильных.
4. Проверить, что `document.documentElement.scrollWidth <= window.innerWidth` на всех страницах при 360px.
5. Формы генератора на мобильных — в одну колонку, кнопка «Сгенерировать карточку» sticky снизу, чтобы не искать её скроллом.

**Критерий приёмки.**
- На 360px и 390px нет горизонтального скролла ни на одной странице.
- С телефона доступны все 4 раздела навигации.
- Ничего не обрезано и не наложено друг на друга в шапке.

## P0-3. Кнопка «Создать проект» в пустом состоянии дашборда ничего не делает

**Проблема.** На `/dashboard` при отсутствии проектов в центре пустого блока есть кнопка «+ Создать проект». Клик не вызывает ничего: URL остаётся `/dashboard`, состояние не меняется. Кнопка «+ Новый проект» справа сверху при этом работает корректно.

**Что сделать.** Повесить на кнопку пустого состояния тот же обработчик/переход, что и на «Новый проект».

**Критерий приёмки.** Клик по «Создать проект» открывает страницу нового проекта. Заодно пройти по всем кнопкам приложения и убедиться, что мёртвых нет.

# P1 — ломает доверие и конверсию

## P1-1. Долгие операции без внятной обратной связи

**Проблема.** «Написать промпт» отрабатывает ~12 секунд, «Сгенерировать карточку» ~20–25 секунд. Всё это время пользователь видит только крутящийся спиннер — непонятно, работает ли что-то и сколько ждать.

**Что сделать.**
1. Пошаговый индикатор с текстом стадии: «Анализирую товар…» → «Пишу промпт…» → «Рисую карточку…» → «Готово».
2. Прогресс-бар с ожидаемым временем («обычно 20–30 секунд»).
3. Скелетон в области результата вместо пустого прямоугольника.
4. Возможность отменить операцию (`AbortController`).
5. Блокировать повторный клик на время выполнения (сейчас кнопка блокируется — сохранить это поведение).

**Критерий приёмки.** На протяжении всей генерации на экране есть меняющийся текст стадии и понятно, сколько осталось.

---

## P1-2. Нет обработки ошибок

**Проблема.** Не предусмотрены сценарии: fal.ai недоступен, кончился баланс, таймаут, модель вернула ошибку модерации, у пользователя отвалился интернет. Сейчас пользователь в этих случаях получит либо вечный спиннер, либо ничего.

**Что сделать.**
1. В API-роутах ловить ошибки и возвращать типизированный ответ: `{ error: { code, message } }`, коды — `RATE_LIMITED`, `PROVIDER_ERROR`, `TIMEOUT`, `INVALID_INPUT`, `CONTENT_REJECTED`.
2. На клиенте — тост с человеческим текстом на русском и кнопкой «Повторить». Никаких `Error: 500` и стек-трейсов пользователю.
3. Таймаут запроса к провайдеру (60 c) с корректным сообщением.
4. Автоповтор один раз при сетевой ошибке.
5. Логировать ошибки провайдера на сервере (`console.error` + структурированный объект), чтобы их было видно в логах Vercel.

**Критерий приёмки.** При недоступном провайдере (проверить, подставив заведомо неверный ключ в локальном `.env`) пользователь видит понятное сообщение и кнопку «Повторить», а не зависший спиннер.

## P1-3. Превью не совпадает с тем, что скачается

**Проблема.** Тумблер «Наложить заголовок на карточку» включён по умолчанию, но в превью никакого заголовка нет. Пользователь не понимает, что получит в файле.

**Что сделать.**
1. Рендерить наложение заголовка прямо в превью — тем же кодом, что и при экспорте (общий компонент / общая функция отрисовки на canvas).
2. Переключение тумблера мгновенно меняет превью.
3. Дать минимальный контроль: положение (верх/низ), размер, цвет текста и подложки.

**Критерий приёмки.** Превью пиксель-в-пиксель соответствует скачанному файлу (с точностью до масштаба).

---

## P1-4. Заявленный размер не совпадает с фактическим

**Проблема.** В селекте «Размер» указано `900 × 1200 · 3:4`, фактическая картинка — `896 × 1200`.

**Что сделать.** При экспорте приводить изображение ровно к выбранному размеру (`sharp` на сервере или canvas на клиенте), с `cover`-кропом по центру. Поддержать все заявленные пресеты: 900×1200, 1200×1600, 3:4, 4:5. Формат PNG/JPG — как выбран, для JPG качество 90.

**Критерий приёмки.** Скачанный файл имеет ровно те размеры, что выбраны в интерфейсе (проверить в свойствах файла).

## P1-5. Результат не соответствует формату карточки Wildberries

**Проблема.** На тестовом запросе «Термокружка из нержавеющей стали 500 мл» с типом «Главная обложка» модель вернула красивый студийный рендер термо-бутылки: во-первых, не тот товар (бутылка вместо кружки), во-вторых — без единого элемента карточки: нет заголовка, нет плашек с преимуществами, нет акцентов. Это фото товара, а не продающая карточка.

**Что сделать.**
1. **Разделить слои.** Модель генерирует только фон/сцену с товаром, а текстовый слой (заголовок, 3–4 плашки преимуществ, бейджи) накладывать программно — canvas/SVG поверх изображения. Так текст всегда читаемый, кириллица не ломается, а результат предсказуем.
2. **Шаблоны компоновки** под каждый из 12 типов карточек: где заголовок, где плашки, где место под товар. Промпт для модели должен явно резервировать это место («оставь верхнюю треть свободной под заголовок»).
3. **Уточнять товар в промпте.** Сейчас модель уходит от исходного объекта. Добавить в системный промпт жёсткое требование сохранять тип товара, а при загруженном фото — использовать image-to-image, а не text-to-image.
4. Добавить кнопку «Не тот товар / перегенерировать» с усилением якоря на название.

**Критерий приёмки.** На тестовом наборе из 5 товаров разных категорий (кружка, футболка, крем, наушники, коврик) результат — карточка с читаемым русским заголовком и плашками преимуществ, товар соответствует названию.

## P1-6. Сайдбар уезжает при скролле

**Проблема.** Сайдбар не зафиксирован: на длинных страницах (`/generator` с результатом) он скроллится вместе с контентом, и навигация уходит за верхнюю границу экрана. Подсказка внизу сайдбара при этом висит оторванным блоком.

**Что сделать.** Сайдбару — `sticky top-0 h-screen` со своим внутренним скроллом (`overflow-y-auto`), подсказку прижать к низу через `mt-auto`. Шапка контента уже фиксирована — проверить, что они не перекрывают друг друга.

**Критерий приёмки.** При скролле любой страницы навигация всегда видна.

---

## P1-7. Примеры карточек на лендинге — цветные заглушки

**Проблема.** Блоки в hero и в секции «Примеры карточек» — это градиентные прямоугольники с подписями. Для сервиса, который продаёт изображения, отсутствие реальных примеров — главный стопор конверсии.

**Что сделать.**
1. Сгенерировать 6–12 реальных карточек по разным категориям и положить в `public/examples/` (WebP, `next/image`, `loading="lazy"`).
2. Формат «до / после»: слева реальный скриншот слабой карточки с выдачи WB, справа результат сервиса. Это работает сильнее одиночных картинок.
3. Клик по примеру — лайтбокс с увеличением, под ним подпись с типом карточки и категорией.

**Критерий приёмки.** В секции «Примеры» нет ни одного градиента-заглушки; все изображения — реальные результаты продукта.

# P2 — техническая гигиена и SEO

## P2-1. Кастомная страница 404

Сейчас на несуществующем маршруте отдаётся дефолтная чёрная страница Next.js с английским текстом «This page could not be found». Сделать `app/not-found.tsx` в стиле сайта, на русском, с кнопками «На главную» и «В генератор». Заодно добавить `app/error.tsx` для необработанных ошибок рендера.

## P2-2. Метатеги и превью ссылки

Сейчас в `<head>` есть только `title`, `description` и `viewport`. Отсутствуют:

- `openGraph`: `title`, `description`, `url`, `siteName`, `locale: 'ru_RU'`, `type: 'website'`
- `og:image` 1200×630 — сделать через `app/opengraph-image.tsx` (динамическая генерация) или статический файл
- `twitter: { card: 'summary_large_image' }`
- `canonical` через `alternates.canonical`
- `favicon` / `app/icon.png` / `apple-icon.png`
- `app/robots.ts` и `app/sitemap.ts`

**Критерий приёмки.** Ссылка на сайт, отправленная в Telegram и WhatsApp, разворачивается в карточку с картинкой и описанием.

## P2-3. Аналитика

Подключить Яндекс.Метрику (с вебвизором) и/или Vercel Analytics. Отправлять события: `generate_prompt`, `generate_image`, `download_card`, `analysis_run`, `project_created`. Без этого невозможно понять, на каком шаге отваливаются пользователи.

## P2-4. Свой домен

`*.vercel.app` для платного сервиса выглядит несерьёзно и хуже индексируется. Купить домен, привязать в Vercel, настроить редирект с `vercel.app` на основной.

## P2-5. Доступность и мелочи интерфейса

- У картинки-превью `alt="Превью карточки"` — ок; проверить остальные изображения после замены заглушек.
- Кнопкам-иконкам (переключатель темы, бургер) добавить `aria-label`.
- Проверить фокус-стили на всех интерактивных элементах (навигация с клавиатуры).
- Селекты «Размер» / «Формат» / «Стиль» — проверить работу с клавиатуры.
- Добавить `<html lang="ru">` — уже есть, оставить.

## P2-6. Защита API от злоупотреблений

> Если это уже покрывается вашей работой над регистрацией — пропустить.

Роуты `/api/ai/generate/text` и `/api/ai/score` вызываются без какого-либо токена. Независимо от авторизации имеет смысл добавить:

- rate limit по IP (Upstash Redis / Vercel KV): например 10 запросов в час на анонима;
- валидацию входных данных (`zod`): длина названия, количество преимуществ, размер загружаемого файла;
- проверку `Origin`/`Referer` для отсечения простейшего внешнего использования;
- ограничение размера загружаемого изображения (напр. 10 МБ) и белый список MIME-типов.
